# 21. Data & Security

**What data does KAIRON collect?** — Asset, security, regulatory and business-risk data needed to assess the institution.

**Where is it stored?** — In secure infrastructure with storage based on the customer's requirements.

**Is it tenant isolated?** — Yes, each institution's data is kept logically separate.

**Is it encrypted?** — Yes, both in transit and at rest.

**Who can access it?** — Only authorized users with role-based access.

**How are privileged users controlled?** — Least-privilege access, strong authentication and activity logging.

**Are actions audited?** — Yes, important system and user actions are logged.

**How is evidence protected?** — Through encryption, access controls and audit trails.

**Can customers export their data?** — Yes, customers should be able to export their own data.

**What happens after contract termination?** — Data is returned or securely deleted according to the agreed policy.

**What data do we retain?** — Only the data necessary to provide the service and maintain required audit records.

**Can KAIRON itself become a high-value target?** — Yes, so KAIRON's own security has to be treated as critical infrastructure.

**What happens if KAIRON is compromised?** — We contain the incident, investigate it, notify affected parties as required and restore the system securely.

**What is our incident-response model?** — Detect → Contain → Investigate → Notify → Recover → Improve.
