# 32. Prototype Honesty

**What is real?** — Our core architecture, risk model, optimization formulation and prototype workflow.

**What is simulated?** — The quantum execution and enterprise environment are simulated for the prototype.

**What data is synthetic?** — The bank/fintech asset, risk, cost and financial-exposure data used in the demo.

**What API is mocked?** — Any enterprise security, cloud or banking API that we cannot access during the prototype.

**What regulation sources are real?** — The regulatory documents we explicitly connect to KAIRON are sourced from official publications.

**What quantum backend is simulated?** — The QAOA experiment can run on a simulator rather than claiming production quantum hardware.

**What financial-loss values are assumptions?** — Any ₹ loss, probability, remediation cost or risk-reduction value based on synthetic assumptions is clearly labelled as such.

**What benchmark results are actual?** — Only results we actually run and record on the same problem for both classical and quantum approaches.

**What claims are hypotheses?** — Future quantum advantage, insurance adoption, cross-institution network effects and production-level financial savings.

**What claims require production validation?** — Real-world risk reduction, regulatory acceptance, customer ROI, insurance use and scalable quantum advantage.

**What is our honesty statement?** — "We clearly separate what we have demonstrated today from what we believe can be achieved in production."
